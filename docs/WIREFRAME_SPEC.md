# Wireframe Specification

Extracted from `Human Resource Management System - 8 hours.excalidraw`
(574 elements: 299 text, 117 rectangles, 100 lines, 20 arrows, 19 images).

**The wireframe is more detailed and more current than the PDF, and where the
two disagree, this document treats the wireframe as authoritative.** It answers
most of the open questions in `ANALYSIS.md` and contradicts the brief on
several points — see `ANALYSIS.md` §2 for the conflict list.

Note the filename: **8 hours**. That is the build budget.

---

## 0. Global

**Top navigation (all pages):** `Company Logo | Employees | Attendance | Time Off`

**Avatar (top-right):** clicking the profile picture opens a dropdown with
**My Profile** and **Log Out**.

A **Settings** item also appears near the employee-list screen.

The system is **company-scoped**: sign-up captures a Company Name and logo, the
nav shows the company logo, and the Login ID is prefixed with a company code.

## 1. Authentication

### 1.1 Sign In
Fields: `Login Id/Email`, `Password`. Button: `SIGN IN`.
Link: "Don't have an Account? Sign Up".

### 1.2 Sign Up — this is *company/admin* registration, not employee self-service
Fields: `Company Name`, `Name`, `Email`, `Phone`, `Password`,
`Confirm Password`, `Upload Logo`. Button: `Sign Up`.
Link: "Already have an account? Sign In".

### 1.3 User creation — verbatim rule from the wireframe

> - Normal user cannot register, so when the HR officer or Admin creates a new
>   user/employee, there ID should also be created with this method.
> - There password should be auto generated for the first time by the system.
> - They can login and change the system generated password.

So: **employees never self-register.** HR/Admin creates them, the system
generates their Login ID and a first-time password, and the employee changes it
after first login. This requires a *must-change-password* flag on the account.

### 1.4 Login ID generation — verbatim rule

> The Login ID should be automatically generated by the system in the following
> format:
> `[OI (first two letters of the employee's first and last name) (year of joining) (serial number of joining)]`
>
> Example: **OIJODO20220001**
>
> - `OI` → Odoo India (Company Name)
> - `JODO` → First two letters of the employee's first name and last name
> - `2022` → Year of Joining
> - `0001` → Serial Number of Joining for that Year

Format: `<2-letter company code><2 letters of first name><2 letters of last
name><4-digit joining year><4-digit serial>`. The serial resets per year, which
means a per-company-per-year counter and a uniqueness constraint.

## 2. Employees (Admin / HR)

List screen with `NEW` button and a `Search` field. Employees render as
**cards**, not a table.

> Each card should display the employee's profile picture and some basic
> information.
> At the top-right corner of each card, there should be an icon indicating the
> employee's attendance or work status.
> - 🟢 Green dot: Employee is present in the office.
> - ✈️ Airplane icon: Employee is on leave.
> - 🟡 Yellow dot: Employee is absent. (Employee has not applied time off and is absent.)

> Make these cards clickable, and on click, the employee information page should
> open in a view-only (non-editable) mode.

The three status icons are **derived at render time** from today's attendance
and approved time-off — they are not a stored field.

## 3. Employee profile

Header fields: `Login ID`, `Email`, `Mobile`, `My Name`, and on the right
`Company`, `Department`, `Manager`, `Location`, `Job Position`.

Tabs: **Resume**, **Private Info**, **Salary Info**, **Security**.

> Salary Info tab should only be visible to Admin.

- **Resume** — `About`, `Skills` (+ Add Skills), `Certification`,
  "What I love about my job", "My interests and hobbies". Body copy in the
  wireframe is Lorem Ipsum, i.e. free-text fields.
- **Private Info** — `Date of Birth`, `Nationality`, `Gender`,
  `Marital Status`, `Personal Email`, `Residing Address`, `Date of Joining`;
  and **Bank Details**: `Account Number`, `Bank Name`, `IFSC Code`, `PAN No`,
  `UAN NO`, `Emp Code`.
- **Salary Info** — see §4.
- **Security** — present as a tab; contents not drawn.

"My Profile" opens the employee's own profile in form view.

## 4. Salary Info (Admin only) — the largest module

Header: `Month Wage 50000` / `Month`, `Yearly wage 600000` / `Yearly`,
`No of working days in a week`, `Break Time`.

### 4.1 Verbatim rule

> The Salary Information tab allows users to define and manage all
> salary-related details for an employee, including wage type, working
> schedule, salary components, benefits. Salary components should be calculated
> automatically based on the defined Wage.
>
> - **Wage Type**: Fixed wage.
> - **Salary Components**: Section where users can define salary structure
>   components. Each component should include: Basic, House Rent Allowance,
>   Standard Allowance, Performance Bonus, Leave Travel Allowance, Fixed
>   Allowance.
>   Computation Type: Fixed Amount or Percentage of Wage.
>   Value: Percentage field (e.g., 50% for Basic, 50% of Basic for HRA,
>   Standard Allowance 4167, Performance Bonus 8.33%, Leave Travel Allowance
>   8.333%, Fixed allowance is = wage − total of all the component)
>   Salary component values should auto-update when the wage amount changes.
>   **The total of all components should not exceed the defined Wage.**
> - **Automatic Calculation**: The system should calculate each component
>   amount based on the employee's defined Wage.
>   If Wage = ₹50,000 and Basic = 50% of wage, then Basic = ₹25,000.
>   If HRA = 50% of Basic, then HRA = ₹12,500.
>
> Each fields for configuration (e.g., PF rate 12%). and Professional Tax 200

### 4.2 Component table as drawn

| Component | Amount (₹/month) | % | Basis |
|---|---|---|---|
| Basic Salary | 25,000.00 | 50.00 | of Wage |
| House Rent Allowance | 12,500.00 | 50.00 | of Basic |
| Standard Allowance | 4,167.00 | 16.67 | of Basic |
| Performance Bonus | 2,082.50 | 8.33 | of Basic |
| Leave Travel Allowance | 2,082.50 | 8.33 | of Basic |
| Fixed Allowance | 2,918.00 | 11.67 | wage − sum of others |

Descriptions drawn alongside: Basic — "Define Basic salary from company cost
compute it based on monthly Wages"; HRA — "HRA provided to employees 50% of the
basic salary"; Standard Allowance — "a predetermined, fixed amount provided to
employee as part of their salary"; Performance Bonus — "Variable amount paid
during payroll… calculated as a % of the basic salary"; LTA — "paid by the
company to employees to cover their travel expenses… calculated as a % of the
basic salary"; Fixed Allowance — "fixed allowance portion of wages is
determined after calculating all salary components".

**Note the percentages are of Basic, not of Wage**, despite the annotation
saying "Percentage of Wage". Only Basic is a percentage of Wage.

⚠️ **The sample numbers do not reconcile.** They sum to ₹48,750, not the
₹50,000 wage. By the stated rule, Fixed Allowance should be
`50,000 − 45,832 = 4,168` (16.67% of Basic), not the 2,918 shown. Treat the
**rule** as authoritative and the drawn figure as a mock-up error.

### 4.3 Provident Fund and deductions

| Item | Employee | Employer |
|---|---|---|
| PF Contribution | 3,000.00 ₹/month, 12.00% | 3,000.00 ₹/month, 12.00% |

"PF is calculated based on the basic salary." Rate configurable (12%).

**Tax Deductions:** `Professional Tax` — 200.00 ₹/month, "deducted from the
Gross salary".

## 5. Attendance

### 5.1 Marking

> Employees can mark their attendance using the Check In/Check Out systray, and
> users can view their attendance records through the Attendance module.

Controls: `Check IN ->` and `Check Out ->`, with `Since 00:00PM` and a status
dot.

> Upon successful Check IN, the red status dot changes to green.

### 5.2 Rules — verbatim

> On the Attendance page, users should see a day-wise attendance of themselves
> by default for ongoing month, displaying details based on their working time,
> including breaks.
>
> For Admins/Time off officers: They can see attendance of all the employees
> present on the current day.
>
> **Attendance data serves as the basis for payslip generation.** The system
> should use the generated attendance records to determine the total number of
> payable days for each employee.
>
> Any unpaid leave or missing attendance days should automatically reduce the
> number of payable days during payslip computation.

Plus a partial note: "If the employee's working source is based on the assigned
attendace" (sentence is cut off in the wireframe).

### 5.3 Admin / HR list view
Search bar; date navigation `< > Date v Day`.
Columns: `Emp`, `Check In`, `Check Out`, `Work Hours`, `Extra hours`.
Sample row: `10:00`, `19:00`, `09:00`, `01:00`.

### 5.4 Employee list view
Month navigation `< > Oct v`, plus three summary tiles:
`Count of days present`, `Leaves count`, `Total working days`.
Columns: `Date`, `Check In`, `Check Out`, `Work Hours`, `Extra hours`.
Sample rows dated `28/10/2025`, `29/10/2025`.

**Work Hours and Extra hours are computed** from check-in/check-out minus break
time, against the configured working schedule.

## 6. Time Off

> Employees can view only their own time off records, while Admins and HR
> Officers can view time off records & approve/reject them for all employees.

### 6.1 Admin / HR view
Sub-nav: `Time Off | Allocation`. `NEW` button, `Searchbar`.
Balance tiles: `Paid time Off — 24 Days Available`,
`Sick time off — 07 Days Available`.
Table columns: `Name`, `Start Date`, `End Date`, `Time off Type`, `Status`.
Actions: **Reject & Approve buttons**.

### 6.2 Employee view
Same balance tiles and table, own records only, with a `NEW` button.

### 6.3 Request form (modal)
Fields: `Employee`, `Time off Type`, `Validity Period` (`May 13` **To**
`May 14`), `Allocation` (`01.00` `Days`), `Attachment:` — annotated
"(For sick leave certificate)". Buttons: `Submit`, `Discard`.

### 6.4 Time off types — verbatim
> TimeOff Types:
> - Paid Time off
> - Sick Leave
> - Unpaid Leaves

**Leave balances exist and are allocated.** The `Allocation` sub-nav implies HR
grants balances per employee per type; the tiles show remaining days.

## 7. What the wireframe does not cover

- The **Security** profile tab is drawn but empty.
- No payslip screen, despite §5.2 saying attendance feeds payslip generation.
- No dashboard/landing screen — "After login the user must land on this page"
  points at the **Employees** list, not a card dashboard as in PDF §3.2.
- No email verification screen anywhere.
- No employee edit form is drawn (only view-only and "My Profile" form view).
- No offboarding, no reports, no notifications.
